Startup and Dock diagnosis
Confirmed in source and actual processes: onefile uses a launcher parent plus
the Python child, extracts dependencies into a fresh temporary _MEI directory,
and loads Python/Qt there. Onedir uses one process and the installed Frameworks
and Resources trees. A process sample of v3.13 resolved Python, Qt and SDL from
the temporary extraction directory. This is strong evidence that unpacking and
startup loading contribute materially to the delay, consistent with PyInstaller
documentation. It does not quantify how much is decompression vs OS scanning.

The official app's plist points to icon-windowed.icns (PyInstaller artwork).
The source spec gates a missing assets/icone_ngpcraft.icns to None. Later Qt
setWindowIcon uses the actual assets/icone_ngpcraft.ico. A captured launcher icon
was the PyInstaller logo. Candidate bundle icon is converted from that existing
official ICO and Finder displays it correctly; no AI artwork was used.

The parent/child handoff and different bundle/runtime icons explain a plausible
mechanism for the reported Dock transition. However, valid 50 ms Dock AX samples
did not reproduce two simultaneously RUNNING NgpCraft Dock items in this session.
Both candidates had a maximum of one running Dock item. Recent, non-running Dock
items and simultaneous test installs must not be counted as duplicate live icons.
Thus the full reported visual transient is NOT proven entirely packaging-caused,
nor accepted as universally fixed. Physical Cmd-Tab and Dock-animation acceptance
on a clean login/first launch remains outstanding.

Finder implementation and icon design
QApplication subclass initializes its pending queue BEFORE Qt's constructor.
It accepts local existing .ngp/.ngc QFileOpenEvents, including early events, and
defers dispatch until Shell and its instance server exist. Reentrant native event
loops cannot recursively switch ROMs. Later explicit opens are not deduplicated.
Use the existing open_from_another_launch path: it handles foreground activation,
outgoing save commits, and confirmation before ending active link sessions.
Command-line socket forwarding is retained. argv_emulation remains False.

There are separate Viewer document entries for ngp and ngc, rank Alternate.
Names: Neo Geo Pocket ROM and Neo Geo Pocket Color ROM.
The final design intentionally mirrors installed melonDS 1.1: extension-based
CFBundleDocumentTypes, NO custom document icon and NO private UTI declaration.
macOS itself composes the folded-corner document, native shadow, official app
badge, and NGP/NGC labels. The earlier hand-drawn ROM document icon was rejected
and removed. Native NSWorkspace icon output was visually inspected for both
extensions and compared with the local melonDS-associated NDS file icon.

No LSSetDefaultRoleHandler, default-app setter, or global association reset was
called. LaunchServices may select this app when it is the only available viewer;
Alternate does not guarantee an unassociated file will remain unassociated.
This Mac had no explicit NGP/NGC override in LSHandlers at inspection time.
Preservation of an existing OTHER emulator preference still needs a test on a
machine with such a preference. Only task-owned test apps were re-registered.

Persistence and update audit
User paths remain unchanged by this patch:
  REPO = resolved executable parent (inside .app/Contents/MacOS when packaged).
  roms, bios.bin, mono BIOS names, thumbnails, covers, library.json and other
  writable UI folders remain based there; native saves, system.ram and system.rtc
  also remain there. Portable config.ini and settings backups use that parent;
  normal QSettings still uses NgpCraft/Emulator. NGPCRAFT_SETTINGS can isolate it.
Read-only ICO, languages and clean-room HLE BIOS use _MEIPASS; native core is at
_MEIPASS/cpp/build/ngpc_core.dylib. Onedir's Frameworks/Resources links support
these same resource lookups. Nothing moves user data into an extraction folder.

IMPORTANT EXISTING RELEASE RISK: writing into the application bundle conflicts
with read-only installs, App Translocation, signed resource seals and replacing
the whole .app during manual updates. A package replacement can discard data
already saved inside Contents/MacOS. This patch preserves existing paths but does
NOT solve that historical design issue. Never replace a user's app without first
preserving its writable data and portable config. A separate migration design
must support legacy discovery, verified copies and rollback before moving data
to Application Support. No automatic migration/deletion was introduced here.

macOS self-install is already disabled by ngpc_update.can_self_install; this
change retains it. Archive distribution must preserve symlinks (ditto is used).
Fresh candidate passed codesign --verify --deep --strict. Signature is ad hoc,
TeamIdentifier absent; not Developer ID signed or notarized. Local spctl says
accepted with 'override=security disabled', so it is NOT evidence that Gatekeeper
first-run checks will pass on another Mac. No Gatekeeper setting was changed.
CFBundleShortVersionString remains the inherited 0.0.0; real release version
metadata and minimum supported OS policy remain separate release work.
